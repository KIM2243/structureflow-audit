# 자동 모의투자 v1

실행 프로필 `PP-H4-M15-M1-close-v1`. 강의의 상승 추세 연속 매매를 보수적으로 규칙화한 실험이다. 강의 전체의 재현이나 수익성 검증 완료를 의미하지 않는다. 하락 공매도·CP 반전 매매·스윕 필수 조건은 포함하지 않는다.

- 확정 4시간 상승 BOS, 보호 저점 기원 구역의 할인 영역을 사용한다. 강의의 임의 구역 판단을 코드로 옮긴 부분은 OHLC 기원봉의 꼬리–몸통 구역이라는 구현 가정이다.
- 실제 관측 시세의 H4 접촉 이후에만 15분 상승 CHoCH(또는 후속 BOS)를 인정한다. 해당 기원 구역 재접촉 이후 1분 상승 전환과 정제 구역 재접촉을 기다린다. 하위 구역의 상위 구역 내 포함은 보수적인 추가 조건이다.
- 1시간 내부 상승 동행, 비용 차감 최소 2R, 거래당 자본 위험 0.5%를 요구한다. 손절은 1분 기원 저점보다 0.1% 아래다. 이는 실험용 버퍼이며 거래소 호가 단위 구현이 아니다.
- 종목별 독립 가상 자본은 미국 10,000 USD / 한국 10,000,000 KRW. 정수 주식 수, 무차입 매수, 한 종목 한 포지션. 편도 수수료와 슬리피지는 각각 5bps. 세금·호가 대기열·부분 체결은 제외한다.
- 진입 후 손절과 목표를 고정하며 4시간 상승 구조 무효화 시 청산한다. 신규 진입 중지 시 기존 보유분의 청산 감시는 지속한다. 청산 요청도 신선한 시세를 기다린다.
- 시작 이전의 신호를 소급 체결하지 않는다. 매수는 처리 시점 현재가, 청산은 관측 시세 및 진입 이후 완성된 1분봉 장벽으로 판단한다. 같은 봉이 손절과 목표를 모두 넘으면 손절을 우선하고 손절 갭은 더 불리한 시가를 반영한다. 체결 추정 시각과 실제 관측 시각을 따로 저장한다.
- 1분봉 원본 없음, OHLC 오류, 다른 종목, Yahoo 보조 시세, 2분 이상 오래된 최종 1분봉은 신규 체결을 차단한다. 정상 관측 3분 공백 후에는 미진입 단계들을 초기화한다. 폐장 동안 청산도 보류하므로 실행 지연 위험이 있다.
- 4시간봉은 기존 세션별 시간봉 4개 묶음이다. 확정봉은 후속봉이 존재하고 명목 시간도 경과해야 한다. 장 마지막 짧은 4시간 묶음의 확정은 다음 세션까지 보수적으로 늦어질 수 있다.
- 1분 진입 대기는 30분, H4 설정은 7일 유효. 같은 설정의 체결 이력은 재시작·재개 후에도 재진입을 차단한다. 실험당 완료 500건 후 신규 진입을 정지하고 모든 체결 기록을 유지한다.
- 상태·현금·체결을 사용자별 D1 한 행에 원자적으로 저장한다. revision 비교 갱신으로 중복 처리 경쟁을 막는다. 이벤트 표시 기록은 최근 100개, 체결 내역은 실험 전체를 보관한다.
- 단순 보유 비교는 첫 정상 관측 현재가 대비 비용 전 가격 수익률이다. 자동 계좌 성과는 비용 후 성과다. 낙폭은 서버 관측 시점의 평가액 기준으로 실제 장중 최대 낙폭과 다를 수 있다.

## 운영

기존 Oracle VM의 별도 `structureflow-auto-paper` 서비스가 사이트의 인증된 tick API를 호출한다. 새 유료 자원은 필요 없다. 가장 오래 확인하지 않은 실험을 하나씩 처리하고 완료 후 5초 쉰다. 각 실험은 최소 15초 간격이며 실제 주기는 실험 수와 시세 응답 시간에 따라 길어진다. 브라우저는 결과만 10초마다 읽는다. 하트비트가 3분 넘게 없으면 시작 버튼을 비활성화한다.

사이트 배포 후 `lib/kiwoom.ts`, `scripts/kiwoom-bridge.mjs`, `scripts/auto-paper-runner.mjs`, `scripts/install-auto-paper.sh`를 같은 디렉터리 구조로 기존 VM에 전송하고 설치 스크립트를 sudo로 실행한다. 기존 비밀값 파일을 재사용하며 인증 정보를 소스에 저장하지 않는다. 설치는 브리지 기존 소스를 백업하고 브리지 상태 확인 실패 시 복원한다.

최종 운영 확인: 두 서비스 active, 인증 없는 tick 401, 로그인한 API의 runtime.ready true, auto=1 차트의 원본 1분봉 존재, 시험 계정 시작/중지와 D1 revision 증가, 창을 닫은 상태에서 lastChecked 증가. 이 확인 전에는 백그라운드 실행 완료로 보고하지 않는다.
